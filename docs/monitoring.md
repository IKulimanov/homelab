# Мониторинг: ops-bot

`ops-bot` — служебный Telegram-бот в стеке `platform`, говорит голосом Бендера из «Футурамы». Он заменил
`simply-monitoring` и Watchtower: шлёт алерты о важном, недельный отчёт и выполняет команды. Отвечает только в чате
`OPS_CHAT_ID`, сообщения из других чатов молча пропускает. Управляет только контейнерами проектов `platform`, `apps`
и `media-stack`.

Сообщения об обновлениях и копиях баз шлют `update.sh` и `backup.sh` напрямую через Telegram API тем же токеном,
поэтому они приходят, даже если `ops-bot` не работает.

## Команды

| Команда | Что делает |
|---|---|
| `/status` | контейнеры, состояние, версия (`sha-…`), сколько работает, активные алерты |
| `/stats` | температура CPU и SSD, загрузка, память, swap, диски, батарея; минимум и максимум за сегодня |
| `/logs <сервис> [строк]` | последние строки лога, по умолчанию 50, максимум 2000; длинный лог приходит файлом |
| `/restart <сервис>` | перезапуск |
| `/stop <сервис>` | остановка после кнопки подтверждения; `ops-bot` себя не останавливает |
| `/start <сервис>` | запуск остановленного |
| `/update` | проверить обновления всех стеков сейчас, не дожидаясь таймера |
| `/usage`, `/topup`, `/balance` | расход и баланс LLM, см. [llm.md](llm.md) |
| `/gif` | GIF для событий, см. ниже |
| `/panel` | одноразовая ссылка входа в веб-панель, см. [panel.md](panel.md) |

Остановленный через `/stop` или `docker stop` сервис обновления не запускают: так задумано.

## Какие сообщения приходят

| Что | Откуда | Категория `OPS_ALERTS` |
|---|---|---|
| температура CPU и SSD | ops-bot, раз в минуту | `temp` |
| место на дисках из `OPS_DISKS` | ops-bot, раз в минуту | `disk` |
| сервис остановился сам: упал с ненулевым кодом, убит из-за нехватки памяти (OOM), перезапускается по кругу; Docker не отвечает | ops-bot, по событиям Docker и раз в минуту | `service` |
| 80 % и 100 % месячного лимита LLM сервиса и общего, расчётный баланс Gemini ниже `balance_alert_usd` или ниже нуля | ops-bot, раз в минуту | `llm` |
| итог обновления контейнеров | `update.sh` | всегда |
| копия баз не сделана | `backup.sh` | всегда |
| недельный отчёт | ops-bot, `OPS_REPORT_AT` | всегда |

Остальные категории выключены, их можно включить в `/srv/secrets/homelab.env`, например
`OPS_ALERTS=temp,disk,service,llm,mem`:

| Категория | Что |
|---|---|
| `mem`, `swap`, `load` | память, swap, load average |
| `battery` | сервер работает от батареи: пропало питание |
| `health` | healthcheck контейнера не проходит (`unhealthy`) |
| `gateway` | шлюз LLM не отвечает, модель без цены в конфиге |

Пересоздать бот после правки `/srv/secrets/homelab.env` (или «Применить» в Сейфе панели):

```bash
cd /opt/homelab && sudo docker compose -f stacks/platform/compose.yaml --env-file /srv/secrets/homelab.env up -d ops-bot
```

Остановка через `docker stop`, `/stop`, `/restart` или обновление алертом не считается. Падение считается
закрытым, когда контейнер проработал 2 минуты без перезапуска.

### Повторы

- «Внимание» приходит один раз.
- «Критично» повторяется раз в час, пока проблема не ушла; с каждым повтором Бендер злится сильнее.
- Когда проблема ушла — одно сообщение «Восстановилось».
- Переход с «Критично» на «Внимание» отдельным сообщением не приходит.

### Пороги

Те же, что были в `simply-monitoring`:

| Что | Внимание | Критично | Переменная |
|---|---|---|---|
| температура CPU, °C | 75 | 90 | `OPS_CPU_TEMP` |
| температура SSD, °C | 55 | 70 | `OPS_SSD_TEMP` |
| диск, % (каждый из `OPS_DISKS`) | 80 | 90 | `OPS_DISK` |
| память, % | 85 | 95 | `OPS_MEM` |
| swap, % | 50 | 80 | `OPS_SWAP` |
| load average за 5 минут на ядро | 2 | 4 | `OPS_LOAD` |
| заряд батареи при работе от неё, % | 20 | 10 | `OPS_BATTERY` |

Порог меняется строкой в `/srv/secrets/homelab.env`, например `OPS_CPU_TEMP=80,92`, и пересозданием бота командой выше.

## Недельный отчёт

По умолчанию в воскресенье в 20:00, время меняет `OPS_REPORT_AT`, например `Mon 09:00`. В отчёте минимум, среднее
и максимум температуры, загрузки, памяти, мест на дисках за 7 дней, падения контейнеров, расход LLM за неделю и за
месяц, баланс. Если бот в назначенное время не работал, отчёт придёт в течение суток после него, позже — нет.

Цифры считает бот. Под ними 2–4 фразы Бендера, их пишет Gemini через шлюз по инструкции
`stacks/platform/config/voice/report-prompt.txt`. Ключ — `install.sh llm-key ops-bot`, лимит — клиент `ops-bot`
в `llm-gateway.yaml`. Без ключа или при ошибке Gemini вместо них готовая фраза из `report-fallback.txt`.

Замеры хранятся в `/srv/ops-bot/data/ops.db` 30 дней.

## Голос и GIF

Первая строка каждого сообщения — факт без шуток, её видно на заблокированном экране телефона. Фраза Бендера идёт
после пустой строки.

**Фразы** лежат в `stacks/platform/config/voice/`: файл — событие, по фразе на строку, строки с `#` — комментарии.
`{name}` заменяется на имя сервиса или диска. Бот выбирает случайную фразу и не повторяет прошлую подряд. Новая шутка —
строка в файле, commit и push: сервер заберёт её `git pull`, бот перечитает файл сам. Нет файла — сообщение без фразы.

| Файл | Когда |
|---|---|
| `temp`, `disk`, `died`, `oom`, `restart-loop`, `docker`, `llm-limit`, `balance` | первый алерт |
| `repeat-1`, `repeat-2`, `repeat-3` | повторы критичного; с третьего — всегда `repeat-3` |
| `recovered` | восстановилось |
| `cmd-restart`, `cmd-start`, `cmd-stop-ask`, `cmd-stopped`, `cmd-denied`, `cmd-update`, `status-ok`, `status-bad`, `help` | ответы на команды |
| `update-ok`, `update-fail`, `backup-fail` | сообщения `update.sh` и `backup.sh` |
| `report-prompt`, `report-fallback` | недельный отчёт |

Выключить голос: удалить строку `OPS_VOICE` из `stacks/platform/compose.yaml`.

**GIF** выбираешь сам в Telegram, файлы остаются у Telegram, бот хранит только ссылки (`file_id`) в `ops.db`:

1. Отправить боту GIF: из поиска `@gif bender fire`, из галереи или файлом `.gif`/`.mp4`.
2. Бот спросит, к какому событию её показывать, — нажать кнопку.

Работает и по-старому: ответить на GIF командой `/gif temp` или отправить GIF с подписью `/gif temp`. `/gif temp`
без ответа берёт последнюю присланную GIF. GIF, пришедшую файлом или видео, бот перезаливает анимацией: копия
мелькнёт в чате и сразу удалится. Видео со звуком Telegram анимацией не делает — такую GIF бот не примет.

`/gif` показывает, сколько GIF у каждого события, `/gif clear temp` убирает все GIF события. На событие можно
повесить несколько, бот выберет случайную.

| Событие | Когда | Что искать в `@gif` |
|---|---|---|
| `temp` | перегрев | `bender fire` |
| `disk` | кончается место | `bender hoarding` |
| `died` | сервис остановился сам, OOM, перезапуски, Docker не отвечает | `bender we're boned` |
| `recovered` | восстановилось | `bender i'm back baby` |
| `update-ok` | обновление прошло | `good news everyone` |
| `update-fail` | обновление не поднялось | `professor explosion` |
| `llm-limit` | лимит LLM | `bender money` |
| `balance` | кончаются деньги на Gemini | `hermes bureaucrat` |
| `report` | недельный отчёт | `bite my shiny metal ass` |
| `backup-fail` | копия не сделана | `bender scared` |

GIF приходит с первым алертом, «восстановилось», обновлением и отчётом; на повторах — только текст. Если текст длиннее
подписи к GIF (1000 символов) или GIF не отправилась, текст приходит обычным сообщением. `file_id` привязан к боту:
после смены токена GIF нужно собрать заново.

## Логи в браузере: Dozzle

Dozzle в стеке `platform` показывает логи всех контейнеров из compose-проектов в реальном времени, с поиском
и фильтром: `http://<LAN_IP>:8889`. Входа нет, поэтому порт слушает только адрес в домашней сети (`LAN_IP`
в `/srv/secrets/homelab.env`, его заполняет `install.sh`). Без `LAN_IP` порт слушает только сам сервер, открыть можно через
`ssh -L 8889:localhost:8889 <сервер>`. Кнопок остановки и перезапуска в Dozzle нет: это делают `ops-bot` и панель.

## Внешний пульс

Если упадёт Docker или весь сервер, `ops-bot` об этом не скажет. Для этого внешний сервис, например
healthchecks.io: создать проверку с периодом 5 минут и запасом 10, её адрес пинга вписать в `/srv/secrets/homelab.env`
как `HEALTHCHECK_URL` и пересоздать `ops-bot` командой выше. В healthchecks.io подключить уведомления в Telegram.
`ops-bot` пингует раз в 5 минут и только когда Docker отвечает.

## Если что-то не так

- **Температура «нет данных».** `ops-bot` читает `/sys/class/hwmon` хоста. На хосте должны работать датчики:
  `sensors` показывает `coretemp` или `k10temp`, а для SSD — `nvme`. Если нет, `sudo sensors-detect` и перезагрузка
  модулей; Docker при этом не трогается.
- **Нет доступа к Docker.** В логе `permission denied` на `docker.sock`: `DOCKER_GID` в `/srv/secrets/homelab.env` не
  совпадает с `getent group docker`. Исправить и пересоздать контейнер.
- **Отчёт без комментария Gemini.** В логе бота `комментарий к отчёту не получен`: нет ключа в `/srv/secrets/ops-bot.env`
  или исчерпан лимит клиента `ops-bot`.
- **Логи самого бота:** `docker logs --tail 100 ops-bot`.
