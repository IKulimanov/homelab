# Панель «Планета Экспресс»

Веб-панель homelab в стеке `platform`, контейнер `panel`. Адрес — `http://<LAN_IP>:8800`, только из домашней сети.
У панели есть `docker.sock`, то есть права root на сервере, поэтому порт наружу не открывается.

## Вход

Паролей нет. Вход — одноразовая ссылка из служебного бота:

1. Написать боту `/panel`.
2. Открыть ссылку. Она живёт 5 минут и работает один раз.
3. Нажать «Войти». Токен тратится только на этой кнопке, поэтому предпросмотр ссылки в Telegram его не съест.

Сессия живёт 30 дней в cookie браузера. «Выйти из штаба» закрывает её сразу.

Запасной вход, если бот не работает:

```bash
sudo docker exec panel /app -login-link
```

Команда печатает такую же одноразовую ссылку.

## Экраны

| Экран | Что показывает | Что можно сделать |
|---|---|---|
| Мостик | приборы (температура CPU, память, загрузка), что горит, последние доставки, графики за 1, 7 и 30 дней, ссылки на медиасервисы | клик по кораблю — фраза Бендера |
| Экипаж | контейнеры `platform`, `apps`, `media-stack`: состояние, версия, CPU и память | перезапуск, остановка, запуск; «Обновить сейчас» |
| Бортовой журнал | лог контейнера в реальном времени, фильтр, пауза | скачать лог; открыть в Dozzle |
| Сейф Гермеса | файлы `/srv/secrets/*.env`, значения скрыты, обязательные ключи отмечены | показать значение на 30 секунд; «Сохранить и применить» |
| Лаборатория | базы `/srv/*/data/*.db`, таблицы, окно SQL | запрос на чтение, выгрузка в CSV; режим записи на 15 минут |
| Бухгалтерия | расход LLM по сервисам к лимиту, общий лимит, баланс, график по дням | записать пополнение или сверить баланс |
| Доставки | история обновлений из `update.sh`, копии баз | откат на прошлую версию, «Вернуть на main», «Заморозить сейчас» |

Подписи сервисов и ссылки на Мостике — в `stacks/platform/config/panel.yaml`. Панель перечитывает файл на каждый запрос.

## Как работают кнопки

Панель сама не запускает `docker compose`. Она пишет файл-триггер, а systemd запускает скрипт на хосте:

| Кнопка | Триггер | Юнит | Что делает |
|---|---|---|---|
| «Сохранить и применить», откат, «Вернуть на main», «Обновить сейчас» | `/srv/panel/trigger/apply` | `homelab-apply.path` | `update.sh auto`: стеки `platform` и `apps` |
| «Заморозить сейчас» | `/srv/panel/trigger/backup` | `homelab-backup-now.path` | `backup.sh --all` |

`update.sh auto` медиастек не обновляет: новые образы медиастека ставятся только ночью. Если в этот момент идёт плановый
прогон, применение ждёт его до 15 минут. Пока идёт прогон, корабль на экране летит, страница сама обновится по итогу.

Перезапуск, остановка и запуск на «Экипаже» идут напрямую через Docker, без триггера.

## Ограничения

- Панель не останавливает и не перезапускает сама себя.
- Только проекты из `PANEL_PROJECTS` (`/srv/secrets/panel.env`), по умолчанию `platform,apps,media-stack`.
- `media.env` в Сейфе только для чтения: правка пересоздала бы весь медиастек. Его правят руками на сервере.
- Откат — только для своих сервисов (`platform`, `apps`) и только на версии `sha-…` из истории.
- Лимиты LLM меняются в git, в `stacks/platform/config/llm-gateway.yaml`; на экране — подсказка.

## Лаборатория

По умолчанию база открывается только на чтение: запрос до 10 секунд, на экране до 1000 строк, в CSV до 100 000.

Режим записи включается кнопкой с подтверждением на 15 минут. Перед включением панель делает копию базы в
`/srv/panel/data/db-backups/`; не сделалась копия — режим не включается. Копии хранятся 7 дней. В режиме записи:

- один оператор за запрос; `ATTACH`, `DETACH`, `VACUUM` и `PRAGMA` с записью запрещены;
- таймаут 2 секунды: бот пишет в ту же базу и ждёт блокировку до 5 секунд, долгий запрос его не уронит;
- каждый изменяющий запрос пишется в журнал действий и уходит в Telegram с именем базы.

Вернуть базу из копии — как из обычной копии, по [backup-restore.md](backup-restore.md), только файл берётся из
`/srv/panel/data/db-backups/`.

## Журнал действий

Каждое действие пишется в таблицу `audit` базы `/srv/panel/data/panel.db` и уходит в служебный чат сообщением
«Панель: …». Значения секретов не пишутся никуда: в журнале только имена изменённых ключей. Показ значения в Сейфе
пишется в журнал, но в Telegram не уходит.

```bash
sudo sqlite3 -readonly /srv/panel/data/panel.db "SELECT * FROM audit ORDER BY id DESC LIMIT 20"
```

## Настройки

| Переменная | Где | Что |
|---|---|---|
| `PANEL_TOKEN` | `/srv/secrets/homelab.env` | общий токен панели и `ops-bot` для ссылок входа; генерирует `install.sh` |
| `PANEL_URL` | `/srv/secrets/homelab.env` | адрес панели в ссылках; пусто — `http://<LAN_IP>:8800` |
| `LAN_IP` | `/srv/secrets/homelab.env` | адрес сервера в домашней сети, на нём слушают панель и Dozzle; заполняет `install.sh` |
| `PANEL_TAG` | `/srv/secrets/homelab.env` | закреплённая версия образа панели; пусто — `main` |
| `PANEL_PROJECTS` | `/srv/secrets/panel.env` | проекты, которыми управляет панель |

## Если что-то не так

- **«запрос не со страницы панели».** Форма отправлена не со страницы панели или браузер не прислал `Origin`.
  Открыть панель по адресу заново и повторить. В логе панели — строка с адресом, который пришёл.
- **`/panel` в боте отвечает ошибкой 401.** `PANEL_TOKEN` пуст или разный у бота и панели: запустить `install.sh`
  и пересоздать `ops-bot` и `panel`.
- **Кнопка «Применить» висит.** Проверить юнит: `systemctl status homelab-apply.path homelab-apply.service`
  и `journalctl -u homelab-apply.service -n 50`. Через 20 минут без прогона панель перестаёт ждать.
- **Нет доступа к Docker.** Как у `ops-bot`: `DOCKER_GID` в `homelab.env` не совпадает с `getent group docker`.
- **Логи панели:** `docker logs --tail 100 panel`.
